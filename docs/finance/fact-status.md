# 财务状态与核验口径

历史字段status：api_only（接口单源）、document_only（披露单源）、verified（既有数值匹配）、conflict（来源冲突）。verified表示有限字段数值一致，不是专业审定，也不自动证明数据来源相互独立。

必须区分：是否取得原文、是否匹配某项数值、是否跨源一致、是否支持研究主张。保持年度/季度、累计/单季、单位/币种、合并/母公司、归母/全体股东、原始/重述口径，不用缺失零值填充。

本轮将引入兼容旧历史的统一状态展示和输出校验，实施结果及规则以该文件后续更新为准。OCR数字必须与原图复核；日期未知材料不能证明历史时点已知。

## 已实施统一状态

`app/fact_state.py` 从旧事实和核对记录派生 `verification`。底层历史不覆写；API、模型上下文和导出共用状态。

| state | 展示 | 含义 |
|---|---|---|
| api_single | 接口单源 | 未完成原文/跨源核对 |
| document_single | 原文单源 | 原文或导入材料取得，不能证明独立核验 |
| cross_source_match | 跨源数值一致 | 披露与API记录存在，交叉数值在原单位容差内匹配 |
| legacy_match | 历史匹配待复核 | 旧verified缺少足够匹配依据；保留旧探索计算 |
| conflict | 来源冲突 | 不用于估值基数 |
| ocr_pending | OCR待复核 | 不用于正式数值基数 |
| missing/unverified | 缺失/来源未确认 | 缺数或状态无法确认 |

每项还附原文摘录、定位、单位、历史日期资格和来源独立性未评估提示。追加PDF、读取网页或模型写“已核验”不会升级状态。

报告保存和对话输出检查“已核验/双源核验”等过度表述；对话允许一次修订，仍失败则明确不采用。规则仅覆盖已知状态词和指标，不代表通用金融语义验证。单源可作标明状态的探索估值，计算不会提高其可信度。
